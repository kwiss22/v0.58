## 1. 게시글 카드 (C06) 변경 — F-COMM-201

### 1-1. 작성자 라인 시각

```
┌────────────────────────────────────────────────────┐
│  [구]  구자호 교수   ●인증 의사     2시간 전          │
│       서울대학교병원 · 정형외과                       │
│  ─────────────────────────────────────────────────  │
│  ※ 본 카드 전체 배경: 옅은 블루-그레이               │
└────────────────────────────────────────────────────┘
```

- **아바타:** 실명 이니셜 + 파란 그라데이션 (마이페이지 M01과 동일 규칙).
- **이름:** 실명. 닉네임 미노출.
- **뱃지:** 이름 우측 «인증 의사» 캡슐 (횡단 정책 2-2 톤 결정).
- **서브라인:** 「소속 병원 · 전문과」 1줄 (전문과 최대 2개, 초과 시 «…»).
- **카드 배경:** 토큰 `--surface-doctor-bubble` 적용.
- **카드 좌측 보더(선택):** 인증 의사 강조용 4px 좌측 컬러바 — 결정 필요.

### 1-2. 정렬 가산 (C04)

- 횡단 정책 2-4 P2 채택 권장.
- 정렬이 «최신순»이라도 동일 시간대(예: ±1시간) 내 인증 의사 글에 가산점 +α 부여.
- 정렬이 «인기순»이라도 추천/공감 점수에 가산점 +α 부여.
- 가산점 수치 α: 결정 필요 (서버 계산, 클라는 응답을 신뢰).

### 1-3. 본문 상세 (PostDetail) 변경

게시글 상세에서도 동일한 작성자 헤더 규칙 적용. 본문 영역 배경 토큰은 카드와 동일.

### 1-4. F-COMM-201 시나리오

- **선조건:** 인증 의사 회원이 커뮤니티에 글을 작성하려 함.
- **정상 흐름:**
  1. C08 «글쓰기 FAB» 탭.
  2. 글쓰기 모달 상단에 안내 노출: «실명·소속으로 게시됩니다» (회색 배너).
  3. 닉네임 입력란은 노출되지 않음.
  4. 게시 완료 → 목록에 «실명+뱃지+서브라인+옅은 블루 카드»로 노출.
- **예외:**
  - 인증 만료 감지 시 → 안내 배너를 «인증이 만료되어 닉네임으로 게시됩니다»로 교체 + 일반 카드 톤으로 처리.
  - 작성 중 인증 상태 변경 (희박): 게시 시점 상태 기준으로 처리.
- **완료 기준:** 같은 화면 내 모든 작성자 표기가 일관됨 (목록·상세·내 활동·검색 결과).

## 2. 댓글 / 대댓글 (이미지 1) — F-COMM-210

### 2-1. 말풍선 시각 규칙

```
[수] 수연맘★               26/03/10
     친절 배려 ★ 5.0  치료 만족 ★ 4.5  쉬운 설명 ★ 4.5
     추천 의향 ★ 5.0
     수술에 대한 두려움이 컸는데, 원장님께서 자분하고…

     공감          댓글 2

  ┌──────────────────────────────────────────┐
  │ [구]  구자호 교수   ●인증 의사     2시간 전 │
  │       서울대학교병원 · 정형외과              │
  │  수연맘님, 좋은 후기 감사합니다. 경과가 좋으  │
  │  시다니 다행이에요. 다음 외래 때 경과 확인하  │
  │  겠습니다.                                  │
  │       공감 8     답글                        │
  └──────────────────────────────────────────┘
   ↓ 위 박스 배경: --surface-doctor-bubble (옅은 블루-그레이)

  [박] 박민수    1시간 전
       저도 구자호 교수님께 수술 받았는데 정말 친절하세요!
       공감 3   답글
```

- **인증 의사 댓글:** 위처럼 **별도 박스 + 옅은 블루-그레이 배경**.
- **이름 라인:** 실명 + «인증 의사» 뱃지.
- **서브라인:** 「소속 병원 · 전문과」.
- **들여쓰기:** 일반 댓글과 동일 들여쓰기 단계 유지 (대댓글은 한 단계 더).
- **공감/답글 버튼:** 디자인 동일.

### 2-2. 우선 노출 — 댓글 영역 P1 (핀)

- 한 게시글의 댓글 트리에서 **인증 의사 댓글이 포함된 스레드**를 댓글 목록 최상단에 핀.
- 같은 스레드 내부에서는 작성 시각 정렬 그대로 유지.
- 인증 의사 댓글이 여러 개일 때: 가장 최근 인증 의사 댓글이 속한 스레드를 우선.
- 일반 댓글의 정렬은 «최신순» 기본값 유지.

### 2-3. 작성기

- 인증 의사가 댓글/대댓글을 입력할 때, 입력란 상단에 회색 1줄 안내:
  - 「실명(소속)으로 게시됩니다.」
- 작성자 자리에는 실명+뱃지가 미리보기로 보일 것.

### 2-4. 면책 고지 (C03 영역)

- 기존: 「이 커뮤니티의 내용은 의료 전문가의 조언을 대체하지 않습니다.」
- 추가 1줄(권장): 「**인증 의사의 댓글도 진료 행위가 아닌 일반 정보 제공입니다.**」
- 게시글 상세 하단 또는 댓글 영역 상단 둘 중 한 군데에 1회 노출 (중복 방지).

### 2-5. F-COMM-210 시나리오

- **선조건:** 인증 의사 회원이 게시글 상세에서 댓글을 단다.
- **정상 흐름:**
  1. 입력란에 안내 「실명(소속)으로 게시됩니다.」 노출.
  2. 작성 → 해당 스레드가 댓글 목록 상단에 핀.
  3. 말풍선은 옅은 블루-그레이 배경, 이름 옆 «인증 의사» 뱃지.
- **예외:**
  - 인증 만료/거절: 핀에서 해제, 일반 댓글 톤으로 회귀.
  - 인증 의사 댓글이 여러 스레드에 걸쳐 있을 때: 2-2 규칙으로 단일 스레드만 핀.
- **완료 기준:** 다른 사용자가 동일 게시글에 진입했을 때도 동일하게 핀과 톤이 적용됨.

## 3. 정렬 가산 — F-COMM-220

### 3-1. 적용 위치

- C04 게시글 목록 (최신순/인기순 모두 적용)
- 홈 H05 추천글 슬롯 (별도 «전문가 의견» 섹션으로 분리하는 안은 횡단 정책 2-4 P3 — 미정).

### 3-2. 가산점 수치

- α 값: **결정 필요**. 권장 초깃값 (튜닝 후 조정):
  - 최신순: 인증 의사 글이면 시간 가산 +30분 상당.
  - 인기순: 인증 의사 글이면 점수 가산 +N점 (전체 평균의 5~10% 수준).

### 3-3. 가시성 균형

- 한 페이지(첫 10개)에 인증 의사 글이 **3개를 넘지 않도록** 제한 (정책).
- 동일 인증 의사가 같은 화면에서 **2개 이상 핀/가산되지 않도록** 중복 차단.

### 3-4. F-COMM-220 시나리오

- **정상 흐름:** 동일 시간/점수대 글이 둘 있으면 인증 의사 글이 위에 노출됨.
- **예외:** 인증 의사 글이 신고로 «검토중» 상태가 되면 가산 즉시 해제.
- **완료 기준:** 사용자에게는 «자연스러운 정렬»로 보이며, 광고처럼 느껴지지 않음.

## 4. 신고 처리 — F-COMM-230

### 4-1. 신고 큐 (정책 5-2)

- **동일 큐 + 운영 지표만 분리** (권장).
- 운영자 화면에서 인증 의사 작성물은 별도 태그로 표시 (즉시 식별 가능).

### 4-2. 콘텐츠 상태에 따른 노출

- **정상:** 위 1·2 규칙대로 노출.
- **검토중:** 카드/말풍선에 «운영자 검토중» 회색 배너 + 본문 흐림 처리. 인증 의사 톤(배경/뱃지)은 **유지**하되 정렬 가산은 **해제** (3-3).
- **숨김:** 본문 블라인드 처리, 상세 진입 차단. 「운영 정책에 의해 가려진 콘텐츠입니다」 안내. 작성자 표기는 노출하지 않음(개인정보 보호).

### 4-3. 인증 의사가 신고 받음 → 운영 처리 강화

- 동일 인증 의사 작성물이 **3회 이상 «숨김»** 처리되면 **인증 자격 재검토** 알림이 운영팀에 전달 (서버 정책).
- 사용자 측에서는 별도 안내 없이 처리.

## 5. 데이터 / API 영향

### 5-1. Post / Comment 응답 (필요 필드)

```ts
{
  id: string,
  authorId: string,
  authorDisplay: {                 // 서버에서 join하여 채움
    name: string                    // 실명 or 닉네임
    isVerifiedDoctor: boolean       // ← 핵심 플래그
    affiliation?: {
      hospital: string,
      specialty: string             // join한 1줄용
    }
  },
  pinned?: boolean,                 // 댓글에서 인증 의사 스레드 핀 시 true
  rankBoost?: number,               // 게시글 가산 점수 (디버깅용)
  status: 'normal' | 'under_review' | 'hidden',
  createdAt, updatedAt, ...
}
```

### 5-2. 클라이언트 신뢰 정책

- 클라이언트는 **서버 응답의 `authorDisplay.isVerifiedDoctor`만** 신뢰.
- 클라이언트가 임의로 «인증 의사» 톤을 켤 수 없도록 디자인 토큰 분기는 이 플래그로만 제어.

### 5-3. 정렬 / 핀 계산

- 클라이언트는 응답 순서를 신뢰. 별도의 클라 가산점 계산 없음.
- 무한 스크롤/페이지네이션 시 가산점/핀이 페이지 경계에서 흔들리지 않도록 서버가 **첫 페이지에 한정**해 핀을 적용 (권장).
