## 1. 우리가 맞추고 싶은 UX

- **관리자·운영** 관점에서 정보를 빠르게 찾고, 실수 없이 처리할 수 있는 **명확한 시각 계층**과 **일관된 패턴**  
- **공통 모달** 등 반복 UI는 **같은 규칙**(여백, 버튼 위치, 확인/취소 순서, 스크롤 영역)으로 통일  
- 의료 맥락에서 **신뢰감**(가독성, 여백, 과한 장식 지양)과 **안내 문구**의 역할이 분명한 화면  

구현은 Figma·화면정의서를 **단일 기준(Single source of truth)**으로 삼고, 코드와 디자인의 차이는 **의도적으로 조정한 경우에만** 합의 후 반영합니다.

## 3. UI·UX 의뢰 범위 (협의용 체크리스트)

**시각·레이아웃**

- Figma와의 **간격·그리드·폰트 크기·행간** 정합 (허용 오차는 협의, 예: 2px 이내 등)  
- **공통 컴포넌트**(버튼, 입력, 탭, 모달, 토스트) 스타일·사이즈 통일  
- **다크/라이트** 또는 브랜드 톤이 정해진 경우 토큰·대비 일관성 유지  

**인터랙션·상태**

- **호버·포커스·비활성·로딩·빈 상태·에러**에 대한 시각·문구 처리 (정의서에 없으면 제안 후 합의)  
- 모달·드로어 **열림/닫힘**, 스크롤 잠금, **포커스 이동** 등 기본 접근성 고려  
- 지도·차트·리스트 등 **데이터 많을 때**의 스크롤·접기·더보기 UX  

**반응형·디바이스**

- 협의한 **브레이크포인트**(예: 관리자용 데스크톱 우선 + 최소 너비)에서 레이아웃 붕괴 없음  
- 터치 영역·클릭 영역이 **최소 권장 크기**를 만족하는지 검토  

**콘텐츠·신뢰(의료 맥락)**

- AI·상담·약물·검사 해석 등 **법·면책·문구**는 기획·법무와 별도 확정; UI는 **경고·보조 설명** 자리를 디자인에 맞게 배치

## 4. 검수·인도 (UX 관점)

| 단계 | 내용 |
|------|------|
| 중간 | 주요 플로우 **스크린 녹화 또는 스테이징 URL**로 화면별 체크리스트 검수 |
| 최종 | Figma 대비 **체크리스트 통과**, 협의 해상도·브라우저(예: Chrome·Edge 최신)에서 시연 |
| 산출 | 화면 캡처 또는 **디자인 QA 이슈 리스트** 클로징 기준 합의 |

기술 산출(Git, 빌드)은 별도 SOW에서 정하되, **“디자인과 동일하게 보인다”**는 UX 기준이 우선입니다.
