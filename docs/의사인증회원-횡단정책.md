# 의사 인증 회원 — 횡단 정책 (Single Source of Truth)

> 이 문서는 **모든 탭(홈·AIGA·명의찾기·커뮤니티·마이페이지)이 공유하는 단일 소스**입니다.
> 화면별 변형 정의는 별도 문서로 분리하며, 이 문서를 참조 링크로만 가져갑니다.
>
> - 마이페이지 변형: `MyPageSpec-인증의사변형.md`
> - 커뮤니티(글/댓글) 변형: `CommunityTabSpec-인증의사변형.md`
> - 명의찾기/홈/AIGA 변형: 추후 동일 패턴으로 분리 예정

## 0. 한 줄 정의

**의사 인증 회원**이란, AIGA가 면허·소속·전문 분야를 검증한 의료진 회원으로,
앱 전역에서 **실명·인증 뱃지·소속 1줄**과 함께 노출되며, 게시물/댓글에 **시각적 강조와 우선 노출**이 적용되는 사용자입니다.

## 1. 역할 모델 (Role Model)

### 1-1. 현재 코드 상태

`src/app/contexts/UserContext.tsx`

```text
type UserRole = 'guest' | 'member';  // 현재 2단계
```

### 1-2. 인증 도입 후 실질 4상태

| 표시명 | 코드 표현 (권장) | 의미 |
|--------|-----------------|------|
| Guest | `role: 'guest'` | 비로그인 |
| Member | `role: 'member'`, `verificationStatus: 'none'` | 일반 회원 |
| Doctor (검토중) | `role: 'member'`, `verificationStatus: 'pending'` | 의사 인증 신청 후 결과 대기 |
| **Verified Doctor** | `role: 'member'`, `verificationStatus: 'verified'` | **인증 완료 — 모든 노출/뱃지/실명 정책 적용** |

### 1-3. 표현 방식 — 결정 필요

세 가지 후보 중 하나로 통일해야 합니다.

- **A. 플래그 추가 (권장):** `role: 'guest'|'member'` + `verificationStatus: 'none'|'pending'|'verified'|'rejected'|'expired'`
  - 장점: 기존 `isGuest/isMember` 분기 그대로 살림. 인증 상태만 별도 축으로 다룸.
  - 단점: 두 축을 동시에 봐야 함.
- **B. role 확장:** `role: 'guest'|'member'|'doctor'`
  - 장점: 한 축으로 단순.
  - 단점: 검토중/거절/만료 같은 중간 상태를 표현하기 어려워 결국 또 플래그가 붙음.
- **C. 별도 user.profile.kind:** `profile.kind: 'general'|'doctor'`
  - 장점: 회원 타입과 인증 상태를 분리.
  - 단점: 두 곳을 관리해야 해 정합성 부담.

→ **결정:** _____ (A/B/C 중 택1)

## 2. 표시 규칙 (모든 탭 공통)

### 2-1. 작성자 표기

- **이름:** 실명 (예: 「구자호 교수」). 닉네임 표시 금지.
- **뱃지:** 이름 옆 «인증 의사» 뱃지 (`VerificationBadge` 재사용 — 톤은 2-2에서 결정).
- **서브라인 (이름 아래 1줄):** `소속병원 · 전문과` (예: 「서울대학교병원 · 정형외과」).
- **아바타:** 실명 이니셜 + 파란 그라데이션 (이미지 2의 「구」처럼).

### 2-2. 뱃지 톤 — 결정 필요

기존 `src/app/components/VerificationBadge.tsx`에 3종이 있습니다.

| type | 색 | 라벨 | 현재 용도 |
|------|----|------|----------|
| `verified` | 파랑 | 병원 진료 인증 | 환자 후기의 «진료 인증» |
| `expert` | 보라 | 의료진 인증 | (사용처 거의 없음) |
| `trusted` | 초록 | 신뢰 사용자 | (사용처 거의 없음) |

→ **결정:** 의사 인증 뱃지는
- (가) 기존 `expert`(보라) 재사용 — 후기 «진료 인증»(파랑)과 톤이 분리되어 혼동 적음.
- (나) 신규 `doctor`(파랑) 추가 — 환자 인증과 동일 파랑 계열로 톤 통일, 단 라벨로 구분.

권장: **(가)** — 환자/의사 인증을 색으로 구분 가능.

### 2-3. 작성자 카드/말풍선 배경 토큰

- 신규 디자인 토큰 1개 정의: `--surface-doctor-bubble`
  - 권장 값: `#F0F5FB` (옅은 블루-그레이) 또는 Tailwind `bg-blue-50/60`
- 적용 위치: 게시글 카드 전체 배경, 댓글/대댓글 말풍선, 의사 프로필 모달의 «AIGA 리뷰» 의사 답글, 챗봇 추천 카드의 작성자 라인.

### 2-4. 우선 노출 정책 — 결정 필요

| 후보 | 동작 | 트레이드오프 |
|------|------|-------------|
| **P1. 핀(Pin)** | 정렬과 무관하게 인증 의사 작성물을 섹션 최상단 1~2개 고정 | 강한 우선, 그러나 «인기»/«최신» 정렬 의도와 충돌 |
| **P2. 가산점** | 정렬 점수에 일정 가중치(+α) 부여 | 자연스러움, 단 가중치 조정 비용 |
| **P3. 별도 슬롯** | «전문가 의견» 같은 별도 줄에 인증 의사 글만 노출 | 시각적으로 분리되어 효과 큼, UI 영역 차지 |
| **P4. 적용 안 함** | 표기만 다르고 정렬은 동일 | 가장 안전, 그러나 «인증 의사» 도입 효과 약함 |

### 2-5. 신뢰성 보호 (보안)

- 클라이언트는 **서버가 검증한 `verificationStatus === 'verified'`만 신뢰**.

## 3. 닉네임 / 실명 정책

### 3-1. 인증 시점 처리

- 인증 완료 시: 표시 이름은 **realName**으로 고정. `nickname` 필드는 백엔드에서 비활성/숨김.
- 인증 이전에 작성된 게시글/댓글/후기의 표기:
  - **권장: 현재 인증 상태 기준으로 재계산 (Join 방식)** — 일관성 ↑, 사용자 신뢰 ↑.
  - 반대안: 작성 시점 표기 보존 (히스토리컬 표기) — 변경 영향 ↓, 그러나 “같은 사람이 다른 이름으로 보이는” 혼란.

→ **결정:** 권장안(현재 상태 기준) 채택? _____

### 3-2. 인증 해제 / 거절 / 만료

- **거절 (rejected):** 표시 이름은 닉네임으로 복원. 뱃지 제거. 사용자에게 사유 안내.
- **만료 (expired):** 「인증 만료」 표기로 6개월(예시) 표시 후 닉네임 복원. 재인증 권유 알림.
- **자발적 해제:** 사용자가 마이페이지에서 인증 해제 시 → 닉네임 복원, 뱃지 제거. 작성물은 정책 3-1에 따름.

### 3-3. 닉네임 백업

- 인증 시점에 직전 닉네임을 `previousNickname` 필드로 보관 → 해제 시 복원에 사용.

## 4. 데이터 / API 메타 필드 (백엔드와의 약속)

### 4-1. User 스키마 (요약)

```ts
User {
  id: string
  role: 'guest' | 'member'
  verificationStatus: 'none' | 'pending' | 'verified' | 'rejected' | 'expired'
  realName?: string            // verified일 때 필수
  nickname?: string             // member일 때 필수
  previousNickname?: string     // 인증 시 백업
  affiliation?: {               // verified일 때 필수
    hospital: string            // 예) '서울대학교병원'
    department: string          // 예) '정형외과'
    specialties: string[]       // 예) ['정형외과', '척추외과']
    licenseId?: string          // 비공개 (서버 전용)
  }
  verifiedAt?: string
  expiresAt?: string
}
```

### 4-2. Post / Comment 작성자 메타

작성 시점에 **저장은 user reference만** 하고 표시는 **최신 user 상태로 join**합니다 (권장 3-1).

```ts
Post / Comment {
  authorId: string
  // 표시 시 join하여 채움 (캐시 가능)
  authorRoleSnapshot: { role, verificationStatus }   // 운영 통계용
}
```

### 4-3. API 응답 정렬 정책

- 정렬 가산점은 **서버에서 계산**되어 응답에 반영 (클라가 재정렬하지 않음).
- 인증 의사 작성물 식별을 위한 응답 플래그: `isAuthorVerifiedDoctor: boolean`.
- 핀(P1) 적용 섹션은 응답에 `pinned: true`를 명시.

### 4-4. 오류/예외 코드

| 상황 | 코드 | 클라이언트 처리 |
|------|------|----------------|
| 인증 만료된 사용자가 의사 전용 액션 시도 | 403 | 「인증이 만료되어 다시 인증이 필요합니다」 안내 + 재인증 진입 |
| 닉네임 변경 시도 (인증 의사) | 403 | 「인증 의사 회원은 실명으로 활동합니다」 토스트 |
| 본인 의사 프로필 후기 작성 시도 | 403 | 「본인 의사 후기는 작성할 수 없습니다」 토스트 (정책 5-1) |
